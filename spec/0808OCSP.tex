\section{Запрос и ответ OCSP}\label{FMT.OCSP}

\subsection{Формат запроса}

Формат запроса OCSP задается типом \code{OCSPRequest}, который определен 
в СТБ~34.101.26. В самом контейнере~\code{OCSPRequest} и во вложенных в него
контейнерах должны быть опущены все опциональные компоненты и компоненты 
со значениями по умолчанию. Единственное исключение делается 
для опционального компонента \code{requestExtensions}, который содержит список  
расширений. Если список включается в запрос, то он должен содержать единственный 
элемент~--- расширение c идентификатором \code{id-pkix-ocsp-nonce}.

Основная информационная часть~\code{OCSPRequest}~--- это список ссылок
на сертификаты, статус которых необходимо проверить.
%
Каждая ссылка описывается контейнером~\code{Request}, который заполняется по
правилам СТБ~34.101.26. Идентификатор алгоритма хэширования, указанный в
компоненте~\code{hashAlgorithm} контейнера~\code{Request}, должен выбираться из
перечня, заданного в~\ref{CRYPTO.Hash}. Дополнительно разрешается
использовать алгоритм SHA-1.

\begin{note*}
Ссылка в~\code{Request} содержит хэш-значения идентификационных данных и 
открытого ключа УЦ, выпустившего проверяемый сертификат. Именно эти 
хэш-значения разрешается вычислять с помощью алгоритма SHA-1, признанного на 
сегодняшний день криптографически нестойким. Существует угроза переадресации 
ссылки с одного УЦ на другой. Однако в ИОК с контролируемыми УЦ эта угроза не 
представляет практической опасности.
%
Разрешение на использование SHA-1 продиктовано необходимостью обеспечивать 
совместимость с действующими системами защиты информации. В тех случаях, когда 
совместимость не нужна, от использования SHA-1 следует отказаться.
\end{note*}

\subsection{Формат ответа}

Формат ответа OCSP задается типом~\code{OCSPResponse}, который определен 
в СТБ~34.101.26. 

Контейнер~\code{OCSPResponse} заполняется по правилам СТБ~34.101.26
со следующими уточнениями.

\begin{enumerate}
\item
В компоненте~\code{signatureAlgorithm} контейнера~\code{BasicOCSPResponse},
вложенного  в~\code{OCSPResponse}, должен быть указан алгоритм ЭЦП из перечня,
заданного в~\ref{CRYPTO.Sign}.

\item
Компонент~\code{certs} контейнера~\code{BasicOCSPResponse} должен быть опущен
либо в этом компоненте должен быть указан единственный сертификат~--- сертификат
отправителя OCSP-ответа.

\item
В контейнере~\code{ResponseData}, вложенном в~\code{BasicOCSPResponse}, должен
быть опущен компонент~\code{version} со значением по умолчанию. Опциональный
компонент~\code{responseExtensions} должен быть либо опущен, либо содержать
единственный элемент~--- повтор расширения с идентификатором
\code{id-pkix-ocsp-nonce} из OCSP-запроса.
%
В компоненте \code{responderID} должен быть сделан выбор в пользу \code{byName}.

\item
В каждом из контейнеров~\code{SingleResponse}, вложенных в~\code{ResponseData},
должен быть опущен компонент~\code{singleExtensions}.

\item
В контейнере~\code{RevokedInfo}, вложенном в~\code{SingleResponse},
компонент \code{revocationReason} должен быть опущен, если сертификат отозван 
по неопределенной причине. Если компонент \code{revocationReason} присутствует, 
то код причины отзыва в нем должен принимать значения, перечисленные 
в~\ref{FMT.CRL}.
\end{enumerate}
